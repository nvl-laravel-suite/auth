# Operations

Use `nvl:auth:doctor`, `nvl:auth:features`, `nvl:auth:configuration` and `nvl:auth:schema` for native readiness. Pruning and principal adoption require explicit system authorization. Preview schema/adoption before apply. Keep source transaction commit, audit retry and queued worker isolation checks enabled. Route registration is outside package readiness.

Schedule `nvl:auth:prune` only after binding a host `SystemMutationAccess` policy that approves `nvl.auth.maintenance.prune`; the default denies both execution and `--dry-run`. Run outside a host transaction so each bounded deletion batch commits independently. `cleanup.batch_size` defaults to 250 and accepts 1..1000. One UTC retention cutoff is retained throughout the run; every deletion repeats its terminal and current ownership predicates, and counts report rows actually deleted. Authority is checked again before selecting and deleting each batch. A failure stops the run and preserves earlier committed batches; retrying is safe. The whole-run success audit is recorded only after all tables finish. A host outer transaction retains its normal commit and rollback boundary.

### Managed browser admission

Managed sessions are opt-in (`features.managed_sessions.enabled=false`). Native proof-backed login privately creates the authoritative row and rotates the per-guard server-session binding. A raw Laravel guard login/actingAs never enrolls a trusted row. Default absolute lifetime is 12 hours; admission heartbeats persist at most once per minute. Native binding hashes and assurance state stay hidden. `AuthClientSession` remains client correlation, separate from browser authority.

Place consumer middleware calling `LaravelSessionAdmission::admit` after session/authentication and before application authorization. Declare `admission_integrated=true` for doctor; this declaration is an integration promise, not automated route proof. Use a server-side driver; cookie payloads are unsupported. Existing untracked sessions must reauthenticate. Revocation is next-admission denial even when a physical payload remains. No public arbitrary-session enrollment API exists.

Session revocation uses native registry UUIDs and operation-bound recent proof. `revokeOthers` cross-checks the nominated current UUID against the server-only admitted binding; a caller cannot preserve a foreign session. Revocation rolls back with domain work. Revoked browsers cannot spend previously issued sensitive-operation grants. After revoking the current browser, the host calls admission/logout before sending its response. The default containment adapter retains Laravel payloads for expiry/GC and never deletes by bare user_id across guard/provider namespaces. Credential lifecycle changes advance the global revision and revoke managed authority. Cross-store cleanup is a host-owned best-effort or durable-retry integration.

Select the Laravel auth driver `nvl-managed-session` explicitly for managed remember-me. It requires Secure/HttpOnly/SameSite cookie configuration and writes encrypted cookie values. The standard Laravel recaller path is disabled in that driver; standard unselected guards retain their own behavior. Native managed remember requires the selected adapter instead of silently falling back. Every resume consumes a per-device credential and creates only primary proof: enrolled MFA must complete before a new binding or replacement cookie is issued. Rotation preserves the original 30-day absolute expiry. Device family revocation, credential revisions, logout and account containment deny descendants and outstanding remembered proofs. Adoption requires fresh login; do not import existing recallers into trusted registry state.

Consumed remember credentials are strictly single-use. A rejected reuse does not automatically revoke the whole device family or create a grace credential. Serialize browser session restoration per cookie/guard: rejection clears the managed cookie, and the package provides no transport response-ordering guarantee for concurrent restorations. Reuse investigation and explicit family containment belong to the host's security policy; the package does not infer whether a rejected replay was theft or a parallel client request.


### Impersonation admission

Enable only after managed browser admission and explicit `ImpersonationAccess` policy are configured. Start requires an original-browser ImpersonationStart recent grant, reason and a 60–1,800 second duration. Admit every request before app authorization, with fresh actor/target eligibility, policy, owner, revision, expiry and browser checks. Start/stop transport rotates binding/session/CSRF. The scoped adapter restores original identity in `finally`, including business exceptions; an unsafe original is logged out. Native security/admin/token mutations are denied within the overlay. Forced revocation requires separate `nvl.auth.impersonations.revoke` authority.

Keep per-request context scoped in long-lived workers. Audit listeners may read captured original/effective references, but jobs cannot serialize or reactivate execution authority. Use the host's business authorization for additional application actions and restrictions.
