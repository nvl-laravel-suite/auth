# Extending

Bind narrow contracts in `src/Contracts` for identity resolution, eligibility, management/system access, audit and optional engines. Inject native service families for operations. Consumer subclasses opt into optional Permission/Sanctum traits. Never use ambient request state as authority. See [PHP API](php-api.md).

For Socialite, register a scoped `SocialIdentityProviderFactory` before the Auth provider. Construct a fresh SDK driver from the current request in every `make` call; see the [factory example](../README.md). The default factory denies acquisition until configured. The optional third SocialiteIdentityProvider constructor argument accepts a provider-specific SocialiteEmailVerification policy; use it only when its verification provenance is supported by the driver. The optional fourth argument is a fixed validated HTTPS issuer, never a callback-supplied value. See [social identity security](security.md#social-identities).

When API tokens are enabled, the selected `ApiTokenManager` must implement `SecurityTokenContainment`, extending `TransactionalApiTokenManager`. Its `connection` returns the actual source connection and `revokeForSecurity` revokes only its package-managed namespace for the canonical principal across all owners. Unsupported or cross-source adapters fail closed before native password writes. Disabled API tokens do not require this capability. The Sanctum adapter compares the exact namespace prefix, including literal underscores; it preserves consumer-owned credentials. Custom `PrincipalSessionContainment` bindings remain supported for account lifecycle containment.

Custom invitation resolvers must return the configured canonical persisted User class, recipient email and actual connection. Proofless signup requires an Eloquent `created` event during that resolver call; cached `wasRecentlyCreated` flags, timestamps and concurrently inserted existing users are not authority. Quiet/raw creation without the scoped creation receipt requires authenticated matching recipient proof. Native receipt collection preserves existing observers and restores the original dispatcher on every exit, including nested resolution. Unique identity conflicts fail closed.
